# www/ — the built site

Generated by `hypnotica build`. Everything here is disposable and everything
here is overwritten. **Never edit it**; edit `content/` and build again.

```sh
hypnotica -s content build -o www --media link
hypnotica serve -o www -p 8080
```

`--media link` symlinks the audio in rather than copying it. That keeps the
build small, and makes the output depend on the original files staying where
they are — right for a local preview, wrong for anything you intend to upload.
Use `--media copy` to produce a directory that stands on its own, at the cost of
a second copy of every recording.

A build prunes files under `www/media/` that nothing claims. Pass `--no-prune`
if something else is also writing there.

## Publishing

The output is static: any web server will do, and nothing server-side is
required. Two things to get right first:

- **`base_url`.** The feeds, the manifest and the offline app bake it in. Set it
  in `content/hypnotica.yaml` or pass `--base-url https://audio.example.com`.
- **HTTPS.** The service worker and offline downloads need a secure context.
  `localhost` counts; a plain-HTTP host does not.

This directory is in `.gitignore` apart from this file.
